# 答辩演示与验收

## 演示顺序（约 5 分钟）

1. 执行 `npm start`，浏览器打开本机端口 3000。
2. 点击“直接分析示例”，展示总分、角色/积木/列表数量。
3. 展开同步性、数据表示的证据，解释 `event_broadcastandwait` 与 `data_addtolist` 如何命中最高等级。
4. 展示改进建议；说明建议需要结合功能，不能为得分堆砌积木。
5. 下载示例并在 Scratch 3 打开，点绿旗与空格，说明静态分析与运行验证的区别。
6. 导出 JSON 报告，刷新网页后从历史恢复报告，再删除记录。
7. 上传一个内容损坏但后缀为 sb3 的文件，展示清晰错误，不污染历史。
8. 执行 `npm test`，展示测试用例与当前结果。

## 可准备的数据

- 仓库自带 `examples/demo.sb3`：有舞台、一个角色、变量、列表、循环、广播和三个事件脚本。
- 在 Scratch 手工保存一个只有绿旗的项目，比较低复杂度统计。
- 在 Scratch 创建参数化自定义积木与 if 嵌套，保存 sb3，检查维度变化。
- 用纯文本文件改名 `broken.sb3` 检查 ZIP 拒绝。

## 常见答辩问题

**为什么不需要 ANTLR？** ANTLR 是参考资料，不是强制要求。sb3 已包含 JSON 结构化积木图，直接解析图即可，无需重新解析文本语言。

**为什么使用 SQLite？** 单机分析历史数据量小，SQLite 提供真实 SQL、事务和持久化，无需额外部署服务。未来可在数据访问层替换为 PostgreSQL。

**如何避免执行恶意代码？** 不加载用户 HTML/SVG、不运行 Scratch VM、不解压资源到磁盘；仅读取大小受限的 project.json，文件名和角色名通过 textContent 输出，SQL 使用参数绑定。

**与官方 Dr. Scratch 一样吗？** 七个维度参考其模型，具体检测规则是公开的课程实现。未进行官方结果一致性验证，不能称为官方评分。

**如何识别重复程序？** 当前比较三块以上的主链模板，作为潜在重构提示，不比较完整语义，也不用于反抄袭。
