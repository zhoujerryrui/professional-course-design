# 评分规则与指标定义

规则版本：`course-1.0`。参考来源是任务书中对 Dr. Scratch 和 Scratch 文件格式的引用。本项目独立设计下表中的具体规则，未声称对照官方实现验证。

各维度取**命中的最高等级**，未命中为 0 分；低等级不必全部命中。例如只使用广播并等待，同步性直接为 3 分。总分是七维之和。

| 维度 | 1 分 | 2 分 | 3 分 |
| --- | --- | --- | --- |
| 抽象与问题分解 | 至少两个顶层脚本 | 存在自定义积木定义 | 存在带参数的自定义积木原型 |
| 并行性 | 同一事件至少两个脚本 | 同一事件至少三个脚本 | 同一事件至少三个脚本且分布在至少两个目标 |
| 逻辑思维 | if / if-else | if-else 或 and/or/not | 条件嵌套或逻辑运算嵌套 |
| 同步性 | wait | broadcast 或接收广播 | broadcast-and-wait 或 wait-until |
| 流程控制 | 有效 next 连接的顺序执行 | repeat / forever | repeat-until / while 或嵌套循环 |
| 用户交互 | 绿旗事件 | 键盘、角色/舞台点击、询问、鼠标输入 | 视频动作/视频报告或音量报告积木 |
| 数据表示 | 运动积木、外观/音量设置或修改 | 变量设置/修改/读取 | 列表读写或显示隐藏 |

## 遍历方法

sb3 是 ZIP；根目录 `project.json` 的 `targets` 包含舞台和角色。每个目标的 `blocks` 是以积木 ID 为键的字典。`opcode` 表示操作类型，`next` 链接后续积木，`parent` 指向父积木，`inputs` 可链接子积木或者保存内联字面量。`fields` 保存变量名、按键和广播消息等选择项。

有效积木数排除 `shadow: true` 的菜单/原型辅助积木，以及数组形式的内联变量记录。自定义参数判断单独读取可能为影子的 `procedures_prototype`，解析其 mutation 的 `argumentnames`。

脚本是 `topLevel: true` 且无 parent 的非影子积木；含事件脚本和可独立拖放的非事件主链。以每个脚本为根，沿 next 和 inputs 的积木引用进行迭代遍历，以 visited 集合避免循环引用导致无限循环。不可达数指无法从这些根访问的有效积木数。

嵌套判断沿 parent 链回溯，带有访问集合。并行事件按 opcode 与字段内容分组（包含键盘键值、广播消息选择）。这反映结构上的并行潜力，不模拟调度，也不能证明实际同时执行。

## 质量指标

- 空事件脚本：事件帽子积木没有 next。
- 疑似重复脚本：至少三个积木的主链，其操作、字段、输入模板完全相同。嵌套引用用占位标记；因此可能存在误报。仅作重构建议。
- 引用告警：有效积木的 next 或 parent 指向不存在的积木。告警最多保留 100 条。
- 类别直方图：有效积木 opcode 第一个下划线之前的前缀计数。
- 证据：每个维度最多展示 8 个相关有效积木；脚本数量推导和影子原型的完整信息可在源码对应规则复核。

## 局限

静态结构不能确定执行次数、角色行为是否符合预期、学习者是否理解代码。孤立顶层积木也可满足部分规则；未知扩展未必参与评分。程序越复杂不一定越好，合理删除积木可能降低分数但提升质量。本系统不采用成绩等级标签，不判定原创性或抄袭。
